# Guardrr

A practice tool for colorguard performers to sharpen toss technique.

## The premise

A metronome plays continuously at your tempo, grouped into phrases (16 counts by default).
A toss prep is typically counted "5 6, 5 6 7 8" and you **release on count 1** of the phrase.
Shortly before the release, Guardrr **speaks a random toss count** (1–7 by default). You release
on 1, **catch on the called count** (a "5" is caught on count 5, a "6" on count 6), keep marking
time until the phrase ends, and the cycle repeats with a new random call.

Calls can be on any count the phrase allows (up to 16 in a 16-count phrase), and optionally on
"and" counts — a "2 and" is caught on the "and" after 2. A "1" is a pop toss, caught on the "and"
of the release. See [docs/colorguard-research.md](docs/colorguard-research.md) for the counting
conventions this is based on.

Today you can press **Start** and practice. The display shows the current count, the toss being
thrown and the next call once it's spoken, flashes **Release!** and **Catch!**, counts down to the
catch, and has a dot per count of the phrase marking the release, the call and the catch.

Under the Start button a **session stats** card shows how many tosses were called, how long
you've practiced, which call came up most, a bar per call and the latest calls (it stays visible
after Stop until the next Start). Tap **Drop** when you drop a toss: it marks the latest toss
(tap again to undo) and the card shows your catch rate and which calls you drop.

**Presets** set up a whole drill in one tap: _Standard 16_, _Quick 8_, _Singles & doubles_
(short tosses with "and" catches), _Big tosses_ (5–8, called 8 counts early) and _Slow 32_.

Below that you can fine-tune:

- **Tempo** — BPM stepper (±1 / ±5) or **tap tempo**; both work while practicing.
- **Phrase** — counts per phrase (4 / 8 / 12 / 16 / 24 / 32), how many counts before the release
  the call is spoken, and the **count-in** before the first toss (4, 8 or a full phrase).
- **Calls** — shortest and longest toss, optional "and" calls, and whether the same call may come
  twice in a row.
- **Sound** — accent on count 1, an optional quiet click on the "and"s, and a vibration on every
  release (count 1) you can feel even when the gym is loud.
- **Voice** — which of the phone's English voices speaks the call (tap one to hear it), how fast
  it's spoken (Slow / Normal / Fast / Faster) and a **Test voice** button to check speed and
  volume before you start.

Phrase, call and sound settings apply on the next Start. Combinations that work but may be
surprising (e.g. the next call spoken before a long toss is caught) are explained under the
settings. Settings are saved on the phone and come back the next time you open the app.
The screen stays on while practicing, and the app follows the phone's light/dark appearance.
With VoiceOver or TalkBack on, Start and Stop are announced (tempo and call count, then the
session summary) and the big display reads its whole state when focused — but the screen reader
never narrates counts during practice, so it can't talk over the metronome or the call.
Defaults: 120 BPM, 16-count phrase, calls 1–7 spoken on count 13 (the "5" of the last
"5 6 7 8"), an 8-count count-in (the first release is 4 seconds after Start) and the "Fast" voice.

## Tech

- [Expo](https://expo.dev) (SDK 58) + React Native + TypeScript
- `expo-speech` for spoken calls, `expo-audio` for metronome clicks (generated by
  `scripts/generate-clicks.js` into `assets/sounds/`), `expo-haptics` for the release buzz,
  `expo-keep-awake` while practicing, `expo-system-ui` for the themed root background,
  `expo-splash-screen` (config plugin) for the launch screen
- App icon, adaptive-icon layers, splash image and favicon are generated by
  `scripts/generate-icons.js` (no dependencies; re-run after changing the artwork)
- Pure, framework-free timing/sequence logic in [`src/engine/`](src/engine) with Jest tests;
  audio in [`src/audio/`](src/audio), the practice session/hook in [`src/practice/`](src/practice),
  saved settings (AsyncStorage) in [`src/storage/`](src/storage), haptics/keep-awake in [`src/feedback/`](src/feedback), light/dark palettes in
  [`src/theme/`](src/theme) (contrast-tested), UI components in [`src/components/`](src/components)
- ESLint (`eslint-config-expo`) + Prettier; GitHub Actions CI runs typecheck, lint, format check and tests

## Development

```bash
npm install
npm start            # Expo dev server — scan the QR code with Expo Go
npm test             # Jest
npm run typecheck    # tsc --noEmit
npm run lint         # ESLint
npm run format       # Prettier
npm run test:smoke   # build for web and run the headless smoke test
npm run check:morning  # everything below, as the morning check runs it
```

### Morning check

Every morning after the overnight build, an automated check runs everything that can be tested
without a phone (`scripts/morning-check.sh`):

1. Typecheck, lint, format check and the Jest unit tests.
2. Builds the **iOS** and **Android** JavaScript bundles (`expo export`), so a change that only
   breaks one platform's bundle is caught.
3. Builds the **web** version and runs `e2e/smoke.js` in headless Chromium: presses Start and
   practices for ~7 seconds, checking the tempo and drift of the clicks, the count-in, when the
   call is spoken and when the release lands, Drop / Undo drop, Stop, that settings survive a
   reload, the dark theme, and that nothing logs an error. Clicks and speech are recorded, not
   played.

It runs in two places: the **Morning check** GitHub workflow (summary, screenshots and logs on
the run page; also runnable by hand from the Actions tab), and a Claude scheduled task that
notifies your phone only when something fails. Real sound, speech, haptics and timing on a phone
still need a hands-on check — each CHANGELOG entry lists what to try.
